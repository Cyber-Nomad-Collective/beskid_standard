# Compiler remediation plan for the canary gaps

Root causes and proposed fixes for the gaps in the [compiler fix list](./Compiler-Fix-List.md), traced in the 0.5.3 compiler source (`beskid_compiler` commit `45ac84fe`, Corelib `82ecd75`) and confirmed with small probe programs on a 0.5.3 build. Paths are relative to the compiler's `crates/` directory unless noted. See [Status](#status) for what is implemented.

## Status

Implemented on a local compiler branch based on 0.5.3 (`45ac84fe`), not yet published; Corelib side on this branch. Each fix has a compiler regression test, and the full `corelib_tests` suite and every canary were run with the rebuilt compiler and runtime kits.

| Canary | Status |
|--------|--------|
| `ParameterShadowsField`, `EmptyConcat`, `MinI64Interpolation`, `BoolInterpolation`, `FieldOnCall`, `GenericLocal`, `InlineEnumArgument`, `ThisMethodCall`, `TimeToUtc`, `CallInArrayLiteral`, `EnumArrayLiteral` | Fixed in the compiler (`TimeToUtc` also needs the Corelib `Time.bd` patch shipped with that compiler build). |
| `NestedField` | Generic owners fixed in the compiler; `value.time.hour` works because `Date`, `TimeOfDay`, and `DateTime` now declare their fields `pub`. Chained projections keep hiding non-`pub` fields of other units, as the compiler's own tests require. |
| `BulkArgs`, `ContractDispatch` | Open: no policy decision needed, larger changes. |
| `FloatToIntCast`, `QualifiedGenericCall`, `FloatInterpolation`, `StringOrdering`, `LambdaCall` | Open: need a decision (NaN/overflow semantics, absolute-path policy) or an OpenSpec/ABI change. |

The same branch also fixes two test failures that 0.5.3 itself has: a static collection test that predates `Storage.AppendAt`, and the `corelib_mvp` fixture lock that predates the networking packages (nine tests). Eight HTTP tests exceed their target execution budget on 0.5.3 with or without these changes.

## How the failures arise

Most gaps share one pattern: the type checker accepts the program, but the query layer in `beskid_queries/src/semantic_contract` that supplies codegen facts declines the shape, so ISLE lowering finds no rule. Two cross-cutting problems make this worse:

- **The ICE points at the wrong node.** A failure inside a nested ISLE rule does not set `pending_error` (`beskid_isle/src/context.rs:362-371`), so the error is reported on the outermost expression. `Make().x` reports `CallExpression` although the member access failed. Recording the innermost failure would make every remaining gap cheaper to diagnose.
- **The checker accepts what codegen cannot lower.** Where a shape stays unsupported, the checker should reject it with a diagnostic instead of letting it reach an internal compiler error (for example `f64` arguments to `i64(...)`, which OpenSpec already says stay unavailable before codegen).

`docs/isle-lowering-coverage.md` in the compiler repository claims a rule for dynamic calls that does not exist; update it alongside these fixes.

## Phase 1: small, low-risk fixes

| Gap | Root cause | Fix | Test |
|-----|------------|-----|------|
| `ParameterShadowsField` (silent miscompile) | The resolver is right (`beskid_analysis/src/resolve/resolve_refs/types_paths.rs:50` puts locals first), but `field_access_receiver` (`beskid_queries/src/semantic_contract/layouts/field_access.rs:143`) maps any bare name that matches a field to the implicit receiver without checking for a local, and codegen trusts that fact (`beskid_codegen/src/isle_adapter/facts_node/shape.rs:33`, `:54`). A `let` local named like a field is affected too. Separately, `beskid_analysis/src/types/checker/expressions/paths.rs:21-30` identifies the implicit receiver by type rather than by local identity. | Add `&& resolve_lexical_declaration(program, index, key.node, name).is_none()` to the `[field]` arm; compare the local's id with `this` in `paths.rs`. Parameters and locals shadow fields. | Query test next to `layouts_and_enums.rs:191` (no field access for a shadowing parameter or local); codegen test in `beskid_codegen/tests/isle_adapter/method_owned_fields.rs`. |
| `EmptyConcat` | `StrConcat` (`runtime/beskid/src/Runtime/Data/Strings.bd:94`, repository root) allocates `totalLen == 0` bytes; the native allocator returns null for size 0 (`beskid_abi/assembly/x86_64-unknown-linux-gnu/platform.S:13-14`), and the null string then compares unequal to `""` and fails to write. `"${s}"` desugars to `"" + s`, so interpolating any empty string is affected. `StrNew` already guards this case. | After the overflow check, `if totalLen == 0 { return StrNew(NativePointer(0), 0); }`. | `StringTests.bd`: `"" + ""`, `"${empty}"`, `("" + "") + "x"`; a JIT case beside `jit_numeric_interpolation_*` in `beskid_engine/tests/corelib_repeat_jit.rs`. |
| `MinI64Interpolation` | `StrFromI64` (`Strings.bd:132-166`) negates the value; `0 - i64::MIN` wraps, so the digit loop never runs and only `-` is written. Corelib's `I64ToDecimal` in `Core/Time/Time.bd:326-345` has the same overflow. | Never negate: loop on `rem != 0`, take `rem % 10` and negate the digit when negative, `rem = rem / 10`; write `-` first. Apply to both. | `i64::MIN`, `-1`, `i64::MAX`, `0`. |
| `BoolInterpolation` | `coerce_expression_to_string` (`beskid_isle/src/context/strings.rs:18`) widens `bool` to `i64` and calls `str_from_i64`, printing `1`/`0`. | Handle `BOOL` first: intern `"true"`/`"false"` through the string interner and select with `brif` into a block parameter. No ABI change. | Beside `parsed_string_interpolation_coerces_i64_operand` (`beskid_codegen/tests/isle_adapter/calls_conversions.rs:111`); `"${true}" == "true"`. |
| `FieldOnCall` | `nominal_field_projection` skips every call target (`field_access.rs:187-189`); the fallback `applied_call_result_layout` requires explicit type arguments and a function, not a method (`field_access.rs:544-553`). `MakeG<i64>(9).x` already works. | Skip only calls with explicit type arguments; route the rest through `generic_source_expression_identity`, which handles direct calls and methods (`calls/generics/expression_identity.rs:119-122`). | `beskid_codegen/tests/isle_adapter/binding_field_receivers.rs`: field of a plain call and of a method call. |
| `GenericLocal` | `emit_local_let` needs the let's scalar type (`beskid_isle/src/context/control_flow.rs:199`); `scalar_semantic_type` (`beskid_codegen/src/isle_adapter/facts_helpers/node_walk.rs:43-70`) never consults the current specialization, which only parameters get (`isle_adapter/context.rs:128`). | When the annotation is a type parameter of the current item, use the specialization's substitution; derive the managed kind from its source identity. | `module_emission_specialization/generic_specialization.rs`: `T first = Array.Get<T>(values, 0)` for `i64` and `string`. |
| `TimeToUtc` (Corelib) | `ToUtcDateTime` and its helpers assign to non-`mut` locals in `Core/Time/Time.bd`. | Apply `docs/patches/time-mut.patch` (verified against 0.5.3) together with the `I64ToDecimal` fix, bump the compiler's `corelib` gitlink in the same commit, and ship compiler and Corelib together: `Time.bd` is embedded with `include_str!` (`beskid_abi/src/runtime_source/sources.rs:231-232`) and trusted only while byte-identical. Applied alone, `Time.Sleep` loses its intrinsics. | `ToUtcDateTime` of instant 0 is 1970-01-01, plus a negative instant, in `TimeTests.bd`. |

| `ContractDispatch` | Member lookup on a `GenericParam` receiver never consults `where` bounds (`call_arguments.rs:213`, `:350`); the query layer returns `None` for parameters typed by an enclosing generic (`contracts.rs:110`, `:193`). | `InlineEnumArgument` | Not yet traced: `h.Pick(Option::None)` lowers once the variant is bound to a local. | Trace like `FieldOnCall` (contextual typing of an enum constructor in argument position). | The canary. |

## Phase 3: features

| Gap | Fix |
|-----|-----|
| `LambdaCall` | Function types have no ABI type (`semantic_contract/abi/types.rs:550`, `layouts/common.rs:497`), there is no rule for calling a function value, and `emit_lambda` (`beskid_isle/src/context/calls.rs:88-110`) drops the capture environment. Represent function values as a GC-managed closure record (the event-handler layout in `beskid_isle/src/context/events.rs:85-110`: code pointer and environment), map function types to that pointer, and add a closure-call rule using `call_indirect`. Needs OpenSpec and ABI work; GC rooting of environments is the main risk. |
| `StringOrdering` | Allow `<`, `<=`, `>`, `>=` on two strings (`literals_operators.rs:68-74`, `checker/helpers.rs:493`), add a string-order operator fact, and lower to a new `str_cmp` runtime service (bytewise, which equals code-point order) or to `Core.String.Compare`. OpenSpec first. |

## Language-surface findings

- **The receiver is `this`.** Methods do not declare `self` (`beskid_analysis/src/resolve/resolve_refs/items_statements.rs:53`, `:78`), but the query layer still treats `self` as an alias (`semantic_contract/locals.rs:26`, `layouts/field_access.rs:606`, `cleanup/escape.rs:119`, `legality/calls.rs:136`). Remove the aliases, or add a diagnostic suggesting `this`.
- **Bare field names resolve inconsistently.** Inside Corelib packages a method can read a field by its bare name (`List.Count` returns `count`), but the same code in a test project reports `unknown value` for plain and generic types alike, while the `ParameterShadowsField` case resolves a bare name to the field. Decide whether bare field names are part of the language; then make resolution, typing, and the query layer agree.
- **A generic type's method cannot return bare `T`.** `pub T Get()` on `Box<T>` reports `unknown type T`; `Option<T>` and `Result<T, E>` returns work.
- **Stale incremental state.** After editing a path-dependency source file, the next run can fail with "source syntax cannot resurrect a fingerprint from an earlier generation" until `obj/` is deleted.

## Corelib follow-up as gaps close

Run `beskid_corelib/tests/canaries/run.sh` against each new compiler build and remove the workaround named in the fix list for every canary that reports `FIXED`: `String.Concat` guards (`EmptyConcat`), `Number.FormatI64` routing (`MinI64Interpolation`), `StringBuilder.AppendBool` (`BoolInterpolation`), one-element `T[]` holders (`GenericLocal`), `Array.Append` chains (array literals), `List.FromArray` (`BulkArgs`), and the per-key `StringMap`/`I64Map` once `ContractDispatch` and `LambdaCall` allow generic hashed maps.
